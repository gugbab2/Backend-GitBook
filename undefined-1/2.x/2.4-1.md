## 보험 계리 에이전트 설계

아래는 공고를 바탕으로 한 설계 연습이다. 회사 내부의 데이터나 실제 업무 책임은 면접에서 확인하는 대상이다.

### 화이트보드 사례 · 상품군 해지율 변동

> 특정 상품군의 월 해지율이 2%에서 3%로 올랐습니다. 계리 담당자가 무엇부터 보는지 설명해 보세요.

1. **지표와 마감을 확인한다.** 해지 이벤트 정의, 분모에 포함하는 계약, 기준일·마감 스냅숏, 상품·판매 채널 필터를 현업과 맞춘다. 해지, 실효, 만기, 부활을 예시에서 섞지 않는다.
2. **데이터를 대조한다.** 원천과 집계 건수, 계약 단위 중복, 늦게 들어온 이벤트, 정정 파일, 상품 코드 매핑, 가정·집계 코드 버전을 확인한다.
3. **기여 구간을 좁힌다.** 상품·채널·가입 경과기간 등 승인된 차원에서 분모·분자·비율·기여를 비교한다. 세그먼트 비중 변화와 세그먼트 자체의 해지율 변화를 구분한다.
4. **가설과 증거를 제시한다.** 계산은 SQL 또는 승인한 계산 코드로 재현한다. 에이전트에는 확정된 수치·계산 기준·출처와 근거를 주고 비교를 설명하게 한다. 관련성은 원인 후보로 표시하고 현업의 확인을 남긴다.
5. **운영에서 되돌아볼 수 있게 한다.** 결과에 기준일, 사용한 데이터·산출 버전, 실행 ID, 확인 상태를 남기고 수치가 바뀌면 새 결과를 구별한다.

**간단한 숫자 예시** — 비교 대상으로 매달 1만 건이 있을 때 200건과 300건의 차이는 100건, 해지율 변화는 **1%p**다. 상대 변화율은 \*\*50%\*\*다. 실제 분모가 달라지면 계약 건수와 비율을 함께 확인한다. 이 숫자는 모의 문제용이다.

### 실제로 풀어볼 실습

**데이터 실습.** 가상의 2개월 계약 스냅숏과 해지 이벤트 테이블을 준비한다. 동일 계약·동일 이벤트 중복, 늦게 유입된 행, 판매 채널 코드 누락, 월말 정정 사례를 하나씩 둔다. SQL과 가능하면 PySpark DataFrame으로 동일한 분모·분자·해지율을 계산한다. 정상 데이터의 2%→3% 예시는 분모가 각각 1만 건일 때만 해지 건수 200→300에 해당한다. 예외 입력에서는 어떤 행을 제외·보류하는지 써 둔다. 조인 전후 건수와 실행 계획을 출력한다.

**에이전트 평가 실습.** 직접 만든 계약 예시와 사내 기준 예시만 사용한다. 필수 지적, 허용 지적, 금지 지적과 출처를 실행 전에 적는다. 전체 자료와 선별 구간의 조건을 동일한 모델·입력으로 비교한다. 결과 건수와 별개로 필수 항목 재현율, 무관 인용, 근거 없음, 지연과 비용을 기록한다. 수행 완료일과 관측값을 남겨 두고, 이 개인 실습은 기획 협업 이력과 구분한다.

**설계 실습.** 사용자 질의 → 권한 확인 → 승인된 지표 조회 → 기준·문서 검색 → 증거가 포함된 설명 → 현업 검토를 그린다. 어느 단계에 데이터 버전을 남기는지, 어떤 경우에 실패로 표시하는지, 각각의 운영 지표를 3분 안에 설명한다.

### 자가 채점표

각 항목 0\~2점. 0점은 빠뜨림, 1점은 원칙만 설명, 2점은 본인의 사례나 구체적인 검증 방법이 들어 있음. 총 12점은 연습용 척도다.

* 본인 역할과 프로젝트 단계를 구분했는가
* 비교 대상과 분모·산출 기준을 말했는가
* 도메인 수치의 근거와 모델 제안을 구분했는가
* 예외·권한·중복·실패 시 처리까지 설명했는가
* 현업의 결정 지점과 설명할 수 있는 근거를 제시했는가
* 아직 검증할 항목을 구체적인 다음 확인으로 연결했는가
